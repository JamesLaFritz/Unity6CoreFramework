BuildProcessing

Source: ./Editor/BuildProcessing.cs

Overview Build automation hooks for the Editor. Provides version bump menus, pre-/post-build processing, and optional Windows installer creation after a successful Standalone build.

Features

  • Build menus (Unity Editor → Core Framework → Build):
    • 0 HotFix or Patch — increments Build
    • 1 New Feature — increments Minor
    • 2 Breaking API Change — increments Major
    • 3 Internal Testing — increments Revision
  • Preprocess: increments the version before the build based on the chosen menu action.
  • Postprocess: writes a Version.txt next to the built player; for Standalone, optionally prompts to create an installer.
  • Installer integration (optional, Windows): runs Inno Setup Compiler if installed and Installers/installer.iss exists.

Quick start

  1. Open Unity and set up your build scenes in File → Build Settings.
  2. Choose one of the Core Framework → Build menu items to trigger a build and bump the appropriate version segment.
  3. After a successful build:
    • A Version.txt file is created in the build output folder containing PlayerSettings.bundleVersion.
    • If platform group is Standalone and you confirm the dialog, Inno Setup will compile the installer.

Installer prerequisites (optional)

  • OS: Windows (uses Microsoft.Win32 registry to locate Inno Setup)
  • Install Inno Setup (iscc.exe). The path is detected via registry key: HKLM\SOFTWARE\Classes\InnoSetupScriptFile\shell\open\command
  • Create an installer script at: ProjectRoot/Installers/installer.iss

Notes

  • Version data is read/written via VersionProjectSettings.instance.CurrentFileVersion and PlayerSettings.bundleVersion.
  • Build output defaults to Assets/../Builds/.exe when using the quick build menu.
  • Only prompts for an installer on Standalone targets.
