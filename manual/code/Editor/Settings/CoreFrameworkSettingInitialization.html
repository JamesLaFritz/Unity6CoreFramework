CoreFrameworkSettingInitialization

Source: ./Editor/Settings/CoreFrameworkSettingInitialization.cs

Overview

Ensures that the editor preferences (CoreFrameworkPreferences) and project settings (CoreFrameworkProjectSettings) are synchronized into the static runtime container CoreFrameworkSettings as soon as the Unity Editor starts.

This guarantees that:

  • Any scripts or tools accessing CoreFrameworkSettings get up-to-date values (ShowDebug, InfoSize, WarningSize, ErrorSize, BootScene, StartScene).
  • Runtime systems such as Bootstrapper can read those values without extra setup.

How it works

CoreFrameworkSettingInitialization is marked with [InitializeOnLoad], so its static constructor runs automatically when the Unity Editor loads.

[InitializeOnLoad]
public static class CoreFrameworkSettingInitialization
{
    static CoreFrameworkSettingInitialization()
    {
        // Load preferences
        var preferences = CoreFrameworkPreferences.instance;
        CoreFrameworkSettings.ShowDebug   = preferences.ShowDebug;
        CoreFrameworkSettings.InfoSize    = preferences.InfoSize;
        CoreFrameworkSettings.WarningSize = preferences.WarningSize;
        CoreFrameworkSettings.ErrorSize   = preferences.ErrorSize;

        // Load project settings
        var projectSettings = CoreFrameworkProjectSettings.instance;
        CoreFrameworkSettings.StartScene = projectSettings.StartScene;
        CoreFrameworkSettings.BootScene  = projectSettings.BootScene;
    }
}

Flow diagram

  1. Editor starts

  2. Static constructor runs.

  3. Reads values from:

    • CoreFrameworkPreferences.instance
    • CoreFrameworkProjectSettings.instance

  4. Writes them into CoreFrameworkSettings statics.

  5. Runtime systems and editor scripts can now just use CoreFrameworkSettings.

Notes

  • This runs only in the Unity Editor (due to [InitializeOnLoad]).
  • In a built player, you’ll need to ensure CoreFrameworkSettings is set up some other way if you’re not using the editor to populate it.
