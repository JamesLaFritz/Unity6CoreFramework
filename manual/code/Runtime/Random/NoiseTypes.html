What each noise “type” actually is

Shared knobs you’ll see a lot

  • Amplitude (amp): vertical scale of the output. output scale.
  • Frequency (freq): how quickly the pattern changes per unit distance. feature size.
  • Octaves: how many stacked layers you sum (each higher octave is smaller scale + lower amplitude).
  • Lacunarity: frequency multiplier per octave (commonly 2.0).
  • Gain / Persistence: amplitude multiplier per octave (commonly 0.5).

Think of an octave stack (also called fBm) as your “how bumpy” control; the base noise function you stack (Perlin, value, Simplex, Worley) sets the character of those bumps.

Core bases

Perlin / Simplex (gradient noise)

  • Produce smooth, band‑limited noise with no sharp grid artifacts.
  • Perlin is lattice‑based; Simplex uses tetrahedra (faster in higher dimensions and easier for analytic derivatives).
  • Output: ~[-1,1]. Great general‑purpose base for terrain, textures.

Value noise (hash‑smoothed)

  • Uses a hash to get a value at lattice points, then smooth‑interpolates.
  • With the right fade curve it’s visually similar to Perlin and plays nicely with stateless PRNGs (perfect for your Squirrel functions).

Worley / Cellular

  • Computes distance to nearest/2nd‑nearest feature points in each cell; outputs distance patterns → “cells/cracks/pebbles/veins.”
  • Not a heightfield by itself; you usually remap/distort it (invert, take min/max, combine with fBm).

Fractal “variants” (they’re just post‑processes / combinations)

fBm (Fractional Brownian Motion)

  • Sum octaves of a base noise (Perlin/value/Simplex).
  • Parameters: octaves, lacunarity (≈2), gain (≈0.5).
  • Output looks like classic rolling mountains.

Billow

  • billow(p) = abs(base(p)) (then optionally re‑center).
  • Rounds valleys into puffy hills. Stack with fBm parameters → “cloudy” terrain.

Ridge / Ridged‑Multi

  • ridge(p) = 1 - abs(base(p)) then sharpen via squaring and biasing.
  • Creates sharp crests; typical for alpine ridges/canyons.

Domain warping

  • Feed noise into the coordinates of another noise: base(p + warp(p)*strength).
  • Breaks repetition, creates flow/“river‑like” structures, gnarly cliffs when used with ridges.

Analytical derivatives

  • Some gradient noises can return (value, ∂value/∂x, ∂value/∂y, …) cheaply.
  • Use derivatives to modulate detail by slope (e.g., reduce high‑frequency detail on steep slopes → pseudo‑erosion).
  • If your base doesn’t expose derivatives, you can approximate with tiny central differences (still stateless & random‑access).

Sean Murray’s “Uber Noise” (No Man’s Sky)

  • A parameterized blender that mixes ridge/billow/base, applies domain warps, and damps by slope/altitude using derivatives.
  • Think: one function with knobs for sharpness, slope erosion, altitude damping, warp strength, plus the usual fBm controls.
  • Squirrel Noise already has the right architectural constraint: stateless, random‑access.

Quick mapping: Squirrel → mental recipes

  • Perlin / Simplex: the base (use our smoothed value noise if you don’t have them).
  • fBm: how you stack (octaves, lacunarity, gain).
  • Billow: abs post‑process of the base (then center).
  • Ridge: 1 - abs with sharpening (then stack).
  • Worley: nearest‑point distance field (use f1, f2, or f2-f1 then remap).
  • Analytical derivatives: value + gradient; use to damp high‑freq on steep slopes.
  • Domain warping: warp coordinates with another fBm (one or two stages) before sampling.
  • Sean Murray’s Uber Noise: a single function that blends base/billow/ridge, applies domain warp, and damps by slope/altitude—implemented above as Uber.

Perlin (gradient noise)

  • What it is: Smooth scalar field built by dotting pseudo-random gradients at lattice corners with the local offset, then easing and trilinearly blending.
  • Feels like: Rolling hills; smooth, band-limited variations.
  • Knobs: frequency (feature size), output scale (amplitude), seed.
  • Continuity: C1 (value + first derivative continuous).
  • Where it shines: Terrain height, clouds, masks, normals (with analytic grad).
  • Gotchas: Axis-aligned if overused; periodic artifacts if you upsample too far.
  • In Unity6CoreFramework.Random lib: Perlin(…), PerlinWithDerivatives(…) (2D/3D core + analytic grad).

Simplex (skewed gradient noise)

  • What it is: Perlin’s sibling on a simplex (triangles/tetrahedra) grid; fewer corners sampled → faster, isotropic patterns.
  • Feels like: Similar to Perlin but slightly “crisper,” less axial bias.
  • Knobs: Same as Perlin.
  • Continuity: C1 (like Perlin).
  • Where it shines: Higher dimensions and cheaper/per-octave use.
  • Gotchas: Patent history (now expired); beware non-standard gradient sets.
  • In Unity6CoreFramework.Random lib: Simplex(x,y,…), Simplex(x,y,z,…) via hash callbacks—no perm tables.

fBm (fractal Brownian motion)

  • What it is: Sum of octaves of a base noise at increasing frequency (×lacunarity) and decreasing amplitude (×gain).
  • Feels like: Self-similar detail across scales; “natural” fractal roughness.
  • Knobs: octaves, lacunarity (≈2), gain (≈0.5), base frequency/amplitude.
  • Where it shines: Mountains, rough textures, masks.
  • Gotchas: Dynamic range grows with octaves → normalize if you want stable [-1,1].
  • In Unity6CoreFramework.Random lib: FBm(baseFn, …); wrappers: SquirrelNoise32Bit.FBm, …64Bit.FBm.

Billow (abs fBm)

  • What it is: fBm of abs(base), remapped back to [-1,1] per octave.
  • Feels like: Puffy, soft pillows; clouds, rolling dunes.
  • Knobs: Same as fBm (abs makes peaks symmetric).
  • Where it shines: Soft cloud cover, fog density, soft ground.
  • Gotchas: Can look too “round” without mixing with other components.
  • In Unity6CoreFramework.Random lib: Billow(baseFn, …) + 32/64 wrappers.

Ridge (ridged multifractal)

  • What it is: Invert and sharpen the absolute value per octave; weight by previous octave.
  • Feels like: Sharp crests, deep valleys—mountain ranges, cracked rock.
  • Knobs: ridgeOffset (~1), ridgeSharpness (≥2), plus fBm knobs.
  • Where it shines: Mountain masks, glacial spines, canyons.
  • Gotchas: Over-sharpening can cause ringing; modulate gain/weight for stability.
  • In Unity6CoreFramework.Random lib: Ridge(baseFn, …) + wrappers.

Worley / Cellular

  • What it is: For each sample, find nearest “feature point” in nearby lattice cells; return distances: F1 (nearest), F2 (2nd), combos like F2−F1.
  • Feels like: Cells, plates, cracks, pebble patterns depending on metric/jitter.
  • Knobs: metric (Euclidean/Manhattan/Chebyshev), jitter (0=centered, 1=free), frequency.
  • Where it shines: Stone, scales, cell membranes, road networks (with post-ops).
  • Gotchas: Value range depends on metric/scale; usually normalize or use F2−F1.
  • In Unity6CoreFramework.Random lib: Cellular2DCore/3DCore + Cellular2D/3D, CellularF1, F2MinusF1.

Worley / Cellular = “worms” vs “blocky”

Wormy (veins, tunnels, tendrils)

Idea: Use Euclidean distance with higher jitter, then emphasize cell edges via F2 - F1, optionally warp the domain so edges bend and weave.

  • Metric: Euclidean
  • Jitter: 0.75–1.0 (features roam inside the cell → organic)
  • Frequency: start low (big features), e.g. 0.002–0.01 in world units
  • Value to use: edge = F2 - F1 (small near edges) → turn into a bright line with an inverse/smoothstep
  • Warping: Apply a low-frequency Domain Warp first to curve the edges
  • Nice remaps:
    • vein = 1 - saturate((F2-F1)/w) (thin veins; w ~ 0.05–0.2 in cell units)
    • vein = exp(-k*(F2-F1)) for smoother, exponential falloff (k ~ 5–15)

Tips

  • Increase jitter for more organic meanders; reduce edgeWidth for thinner/wilder veins.
  • Warp twice (two different seeds/freqs) for “arteries + capillaries”.
  • For cave/tunnel generation: threshold vein > t and run connectivity post-process.

Blocky (cells, tiles, city/brick vibes)

Idea: Choose Manhattan or Chebyshev metrics and keep jitter low so features anchor near cell centers. Edges become straight, grid-like.

  • Metric:
    • Manhattan → diamond/orthogonal facets
    • Chebyshev → square/box facets
  • Jitter: 0.0–0.25 (structured, centered)
  • Frequency: 0.003–0.02 (depending on desired tile size)
  • Value to use: F1 (distance to nearest site) for rounded cells, or F2 - F1 for sharp edges
  • Post: quantize or step to get hard tiling; mix with fBm to add texture variation in each cell.

Tips

  • Manhattan + low jitter is great for streets/blocks; extrude edges as walls.
  • Use the cell id (r.Cell) to seed a per-cell color/height: cellSeed = SquirrelNoise32Bit.Get2DNoise(r.Cell.x, r.Cell.y, seed) then modulate fBm.

Analytical Derivatives (∇noise)

  • What it is: Closed-form gradient of Perlin/Simplex w.r.t. position (not finite diff).
  • Feels like: A vector field pointing “uphill” in the scalar noise.
  • Knobs: None—just pick the base noise & scale via frequency.
  • Where it shines: Flow maps, erosion simulation, normals, advection, curl fields.
  • Gotchas: Make sure your grad matches your exact fade/grad definitions.
  • In Unity6CoreFramework.Random lib: PerlinWithDeriv(…) (2D/3D) returning (value, grad).

Domain Warping (a.k.a. position warp)

  • What it is: Displace the input position by a low-frequency vector field before sampling another (or same) noise.
    • x' = x + A * Wx(x), y' = y + A * Wy(x), z' = z + A * Wz(x)
  • Feels like: Twisted, folded patterns; veins, flowy marbling, rivers.
  • Knobs: Warp amplitude, warp frequency/octaves (warp*), then value stack knobs.
  • Where it shines: Breaking grid-like appearance, creating coherent features.
  • Gotchas: Large amplitude at high frequency can “tear” features; start small, low-freq.
  • In Unity6CoreFramework.Random lib: DomainWarp(baseFn, …) (warps with three independent stacks).

“Uber Noise” (NMS-style composition)

  • What it is: A recipe: stacked warps → fBm base → subtract a ridged component → clamp/normalize.
  • Feels like: Big shapes with believable micro detail; planetary-scale variation that holds up close.
  • Knobs: Two warp blocks (warp1/warp2 Amp/Freq/Octaves), fBm (octaves/freq/gain/lacunarity), ridge mix.
  • Where it shines: Biomes, planet surfaces, large-to-small continuity.
  • Gotchas: Many knobs—tune in stages: warp1 (big), warp2 (medium), fBm, then ridge.
  • In Unity6CoreFramework.Random lib: UberNoise(baseFn, …) (both seeds).

Cross-cutting parameters (quick map)

  • frequency: feature size (↑frequency → smaller features). Often start at 1 and scale your input position instead.
  • amplitude: output scale per octave (top-level).
  • octaves: number of layers in the stack.
  • lacunarity: frequency multiplier per octave (≈2).
  • gain: amplitude multiplier per octave (≈0.5).
  • jitter (Worley): 0 = features centered, 1 = fully random inside cell.

Stateless integration pattern (how Unity6CoreFramework.Random code lines up)

  • Base scalar field: Perlin(...) or Simplex(...) returning ~[-1,1].
  • Fractals: FBm/Billow/Ridge(baseFn, p, seed, …).
  • Gradients: use PerlinWithDerivatives (no extra samples).
  • Cellular: Cellular2D/3D → use F1, F2, F2−F1 or feature positions.
  • Warps: DomainWarp(baseFn, …) then feed into another stack (as in UberNoise).

The two axes to keep straight

  1. Base field (what pattern you’re sampling)

    • Perlin / Simplex (gradient noise)
    • Cellular / Worley (distance-to-features)
    • (Optional) Value noise (hash values + smooth fade-lerp)

  2. Entropy core (how hash integers to “random”)

    • NoiseType enum: MangledBits*, ChaCha*
      • This only changes the bit-mixing used to produce corner hashes / feature jitter. It doesn’t change the macro algorithm—Perlin is still Perlin, Worley is still Worley.

Shared knobs (quick)

frequency = feature size; amplitude = output scale; octaves/lacunarity/gain = fractal stack controls; jitter/metric = Worley flavoring.

The Squirrel “NoiseType” mixers (entropy core)

These feed all the “get hash” calls (Get1D/2D/3DNoise in 32-bit, GetUInt64/… in 64-bit), which in turn feed:

  • Perlin/Simplex (corner hashes → gradient selection)
  • Cellular (cell seeds → jitter vectors)
  • Any per-octave reseeding (MixOctave helpers)

Pick:

  • MangledBitsBalancedMix (default): great avalanche, stable.
  • MangledBitsShiftXOR / MangledBitsRotational: slightly different bias/dispersion; good for decorrelating layers.
  • ChaChaQuarterRoundSimple/Advanced: strong diffusion; nice if you want “very random” local variation.

Mental model: Changing NoiseType is like swapping the hash function under the hood—it alters micro-texture and correlation, not the high-level pattern that Perlin/Simplex/Cellular produce.

Defaults that “just work”

  • fBm: octaves=5–7, lacunarity=2.0, gain=0.5, normalize output.
  • Ridge: ridgeOffset≈1.0, ridgeSharpness=2–3, freq ×1.2–1.6 vs base.
  • Cellular “wormy”: Euclidean, jitter=0.8–1.0, edgeWidth≈0.1 (2D), 0.12 (3D).
  • Cellular “blocky”: Chebyshev or Manhattan, jitter=0.0–0.2.

fBm

  • Start: octaves=5–7, lacunarity=2, gain=0.5, frequency≈0.001–0.01
  • Bigger features: ↓frequency or ↓octaves
  • Finer detail: ↑octaves (normalize output to keep range stable —Squirrel Noise stacks already do)
  • Rougher surface: ↑lacunarity (2→2.2) or ↓gain (0.5→0.45)
  • Smoother surface: ↓lacunarity (1.9) or ↑gain (0.55)

Billow (puffy)

  • Start: same as fBm; often gain=0.55–0.65
  • More “pillow”: ↑gain (amplitudes decay slower)
  • Less symmetric/too soft? Mix in a little standard fBm (0.7*Billow + 0.3*fBm)

Ridge (mountainous)

  • Start: ridgeOffset≈1.0, ridgeSharpness≈2.0–3.0, frequency slightly higher than fBm (×1.2–1.6)
  • Sharper spines: ↑ridgeSharpness (2→3.5)
  • Chunkier ridges: ↑ridgeOffset above 1 (1.1–1.3)
  • Too spiky? ↓ridgeSharpness or ↓frequency

Mixing Cellular with the fractals

  • Wormy rivers over terrain

    1. Get terrain base: height = FBm(Perlin, p3, seed, …)
    2. Get vein mask from Cellular (Euclidean, jitter high): vein ∈ [0,1]
    3. Carve: height -= vein * carveDepth
    4. Optional: domain warp the vein sampling position with a very low-frequency warp so rivers meander.

  • Blocky biomes

    1. Use Cellular2D with Chebyshev, jitter≈0.05
    2. Compute a cell id → pick biome params (different seeds/gains/octaves)
    3. Evaluate fBm/Billow/Ridge per biome to keep features consistent within cells and distinct between cells.

  • Cell edges as roads

    • Threshold F2-F1 < w, then run a thinning/skeletonization if needed.
    • With Manhattan, you get orthogonal “city blocks” almost for free.

Domain warping with helpers

  • Big bend, small twist: warp amps small (0.2–0.8), warp frequencies lower than the value frequency.
  • Two-scale warp (“Uber Noise”): a slow, strong warp (shape), then a faster, weaker warp (detail), then the fBm stack. Squirrel Noise has already codified this in UberNoise.

Final tuning heuristics (quick cheatsheet)

  • Want straighter structure? ↓jitter, switch to Manhattan/Chebyshev.
  • Want more organic curves? ↑jitter, keep Euclidean, add 1–2 domain warps.
  • Thinner lines (worms/roads)? ↓edgeWidth (or ↑k in the exponential remap).
  • Bigger cells/roads? ↓frequency. (Remember all distances scale with your sampling frequency.)
  • Too noisy? Lower the value octaves, not the warp octaves. Keep warps smooth.
  • Terrain too mushy? Add a small Ridge layer (2–3 octaves) and mix it in (0.2–0.4).

Quick “which one should I use?” guide

  • General terrain/masks: Perlin fBm. Add Ridge (mix 0.2–0.4) for bite.
  • Puffy clouds/sand: Billow (abs fBm).
  • Sharp crests/canyons: Ridge.
  • Veins/river networks: Cellular with F2−F1 → CellularEdge01 (Euclidean, high jitter), optionally domain-warped.
  • Tiles/blocks/streets: Cellular (Chebyshev or Manhattan), low jitter, use F1 or F2−F1 + threshold.
  • Slope-aware detail: Use PerlinWithDeriv and reduce high-freq where |∇| is large.
