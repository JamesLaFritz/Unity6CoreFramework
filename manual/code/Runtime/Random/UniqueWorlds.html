How many different unique worlds? How big before repetition?

If a “world” is fully determined by the seed, then the number of distinct worlds equals the number of distinct seeds because the noise is stateless and deterministic.

  • 32-bit pipeline (uint seed): 2³² = 4,294,967,296 unique worlds
  • 64-bit pipeline (ulong seed): 2⁶⁴ = 18,446,744,073,709,551,616 unique worlds

(With our mixers, two different seeds producing the same infinite field would require a pathological collision across every index—practically zero, so count them all.)

When does the world repeat?

Two limits matter:

1) Exact tiling from the integer index combiner

For integer hashing we build indices like

  • 2D: i = x + P1*y (mod 2^N)
  • 3D: i = x + P1*y + P2*z (mod 2^N)
  • 4D: i = x + P1*y + P2*z + P3*w (mod 2^N)

This gives true translational periods: small integer vectors (Δx,Δy,Δz,Δw) where the combination sums to 0 (mod 2^N).

Using our constants:

  • 32-bit (N=32, P1=198,491,317, P2=6,542,989, P3=357,239)

    • 2D: period (P1, −1) → 198,491,317 cells
    • 3D: period (P2, 0, −1) → 6,542,989 cells (shortest)
    • 4D: period (P3, 0, 0, −1) → 357,239 cells (shortest)

  • 64-bit (N=64, P1UL≈1.5486e19, P2UL≈1.4029e19, P3UL≈1.6096e18)

    • 2D: (P1UL, −1) → ≈1.5486e19 cells
    • 3D: (P2UL, 0, −1) → ≈1.4029e19 cells
    • 4D: (P3UL, 0, 0, −1) → ≈1.6096e18 cells

If you sample at frequency f (i.e., p_cell = p_world * f), the shortest repeat distance in world units along those vectors is:

repeat_distance_world ≈ (period_in_cells) / f

Examples (32-bit):

  • 3D, f=1.0 → ~6.54 million units
  • 3D, f=0.01 → ~654 million units
  • 2D, f=0.01 → ~19.85 billion units

64-bit periods are astronomically large—you won’t hit them.

2) Floating-point precision (“detail horizon”)

Unity/world space coords are float. A float has ~24 bits of mantissa, so beyond about 2²⁴ = 16,777,216 in the sampled coordinate space, adding ±1 no longer changes the value after the floor/fraction split used by Perlin/Simplex. In world units:

detail_horizon_world ≈ 16,777,216 / f

So at f=1.0, you keep 1-unit detail out to ~16.8M units. At f=0.01, it’s ~1.68B units.

Which limit bites first?

  • 32-bit hashing: the shortest tiling vector (e.g., 3D (P2,0,−1)) can be smaller than the float horizon at f=1. You could see repeats along that skew direction if you traverse that vector exactly. Along cardinal axes, periods are 2^32 cells—effectively unreachable.
  • 64-bit hashing: the float horizon dominates by many orders of magnitude. You’ll hit precision limits long before any hash tiling.

Recommended max int3 worldSize

Assume your loops visit all integer cells from -worldSize to +worldSize inclusive (so 2*W+1 samples per axis) and step size = 1 cell.

⚠️ Axis reminder (important) Your current call is Perlin( y, x, z, seed ). The 3D index is idx = X + P1*Y + P2*Z. That means world Y → hash X, which is the axis that repeats fastest. Clamp the small bound on world Y with this call order. If you switch to Perlin(x,y,z), move the small bound to world X instead.

Using the 32-bit pipeline (e.g., SquirrelNoise32Bit)

If you sample Perlin/Simplex anywhere (floats involved):

  • Anisotropic safe (with Perlin(y,x,z)): worldSize = int3(8_388_607, 3_271_494, 8_388_607)
  • Cube option: worldSize = int3(3_271_494)

(Numbers come from: shortest 3D period (P2,0,−1) ⇒ keep 2*W_small+1 < P2 → W_small ≤ floor((P2−1)/2) = 3,271,494; and float horizon W ≤ (2^24−1)/2 = 8,388,607 per float axis.)

If you only use integer hash/value noise (no floats):

  • Anisotropic max (with Perlin(y,x,z)): worldSize = int3(int.MaxValue, 3_271_494, int.MaxValue) (practically choose smaller for memory/perf)
  • Cube option: int3(3_271_494)

Using the 64-bit pipeline (e.g., SquirrelNoise64Bit)

  • If you sample Perlin/Simplex: worldSize = int3(8_388_607) (float horizon dominates)
  • If you only use integer hashing/value noise: Effectively unbounded within int; choose by memory/perf.

Frequency scaling

If you pre-scale positions by frequency f before Perlin/Simplex:

  • Float-limited axes (X/Z here): W ≤ floor(8_388_607 / f)
  • Small 32-bit axis (Y here): W ≤ floor(3_271_494 / f)

You can exceed these in practice with origin rebasing (keep the active window near 0 in world→noise space), while keeping 64-bit hashing for stability.

Loop skeleton (inclusive bounds + correct small axis on Y)

const int FloatHorizon = 8_388_607; // (2^24 - 1)/2
const int Small32      = 3_271_494; // floor((P2 - 1)/2), P2 = 6,542,989

// Current call order Perlin(y,x,z): small bound goes on Y.
var worldSize32 = new int3(FloatHorizon, Small32, FloatHorizon);
var worldSize64 = new int3(FloatHorizon);

var W = use32Bit ? worldSize32 : worldSize64;

// Inclusive loops → 2*W+1 samples per axis.
for (int z = -W.z; z <= W.z; z++)
for (int x = -W.x; x <= W.x; x++)
for (int y = -W.y; y <= W.y; y++)
{
    float n = use32Bit
        ? SquirrelNoise32Bit.Perlin( y,  x,  z, seed ) // note (y,x,z)
        : SquirrelNoise64Bit.Perlin( y,  x,  z, seed );
}

64-bit negative-cast tip

When implementing SquirrelNoise64Bit.Perlin, compute lattice coordinates as signed first, then cast to ulong for hashing:

long xi = (long)math.floor(x), yi = (long)math.floor(y), zi = (long)math.floor(z);
float xf = x - xi, yf = y - yi, zf = z - zi;

var h000 = SquirrelNoise64Bit.Get3DNoise(
    unchecked((ulong)xi),
    unchecked((ulong)yi),
    unchecked((ulong)zi),
    seed);

Casting a negative directly to ulong before subtracting the integer part will break the fractional offsets.

How does this compare to UnityEngine.Mathf.PerlinNoise(x, z)?

Short answer: Mathf.PerlinNoise is a handy 2D, seedless, engine-side Perlin with a small, fixed period; Squirrel-based noise is seeded, Burst-friendly, supports 3D, huge periods, and extras like derivatives and cellular.

Unity’s Mathf.PerlinNoise

  • 2D only, signature PerlinNoise(float x, float y) → returns [0,1].
  • No seed (to vary results you offset/scale inputs).
  • Deterministic for same inputs.
  • True period ≈ 256 cells per axis, because classic Perlin uses a 256-entry permutation table. With sampling frequency f, the world-space repeat is ≈ 256 / f.
  • Float precision horizon still exists (~16,777,216 / f), but the 256/f period is the much tighter limit.
  • Not Burst/job friendly (lives in UnityEngine; can’t call it from Burst jobs).
  • No derivatives; gradients require extra samples.

Squirrel Noise pipeline

  • 2D & 3D Perlin (and Simplex, Cellular), all stateless and seeded.
  • 32-bit seeds: 2^32 worlds. 64-bit seeds: 2^64 worlds.
  • Huge periods from integer hashing: in 3D (32-bit) the shortest repeat vector is ~6,542,989 cells (directional), vs 256 for Mathf. In 64-bit, repeats are effectively unreachable; float precision dominates.
  • Burst-friendly, job-safe; analytic derivatives available.
  • Plus Worley/Cellular, ridge/billow stacks, domain warps, etc.

Quick repeat math vs Unity

Let f be the frequency multiplied into world coords before sampling.

  • Unity 2D Perlin: Repeat distance: ~256 / f (hard limit) Precision horizon: ~16,777,216 / f (larger; usually irrelevant)

    • If you loop -W .. +W inclusive, keep 2W+1 < 256/f ⇒ W ≤ floor((256/f - 1)/2).

  • Squirrel 3D Perlin (32-bit): Shortest repeat: ~6,542,989 / f (skew direction) Float horizon: ~16,777,216 / f per axis Use the smaller of those for a conservative bound.

  • Squirrel 3D Perlin (64-bit): Repeat: effectively unreachable; float horizon wins.

If you “fake 3D” with Mathf.PerlinNoise

You can blend slices, but expect axis bias and the same 256/f repeat:

// crude “3D” blend of three 2D slices; still repeats every 256/f
float Perlin3D_Fake(float x, float y, float z, float f) {
    float a = Mathf.PerlinNoise(x*f, z*f);
    float b = Mathf.PerlinNoise(x*f + 37.2f, y*f + 11.5f);
    float c = Mathf.PerlinNoise(y*f + 19.7f, z*f + 53.8f);
    return (a + b + c) / 3f * 2f - 1f; // map to ~[-1,1]
}

Bottom line: for big worlds, 3D, seeds, jobs/Burst, and advanced compositions (derivatives, warps, cellular), the Squirrel Noise pipeline is clearly the better foundation.

TL;DR

  • Unique worlds: 32-bit 2^32, 64-bit 2^64.
  • Practical non-repeat span: min( tiling distance, float horizon ) / f.
  • With Perlin(y,x,z), clamp Y to 3,271,494 (32-bit) and keep X/Z to 8,388,607. For a cube: int3(3,271,494) (32-bit) or int3(8,388,607) (64-bit).
  • Unity’s Mathf.PerlinNoise repeats every ~256/f units; great for small 2D uses, not for large 3D worlds.
