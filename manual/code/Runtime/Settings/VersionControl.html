VersionControl

Source: ./Runtime/Settings/VersionControl.cs (runtime)

Overview

A lightweight runtime container that tracks the project’s file/version information:

  • CurrentFileVersion — the version your content/save format is currently at.
  • MinFileVersion — the earliest version still considered compatible.

These values are set from editor data at load time:

  • VersionInitialization copies values from VersionProjectSettings into VersionControl.
  • Changing VersionProjectSettings.CurrentFileVersion or .MinFileVersion also writes into VersionControl (via the property setters shown on that page).

Unity’s PlayerSettings.bundleVersion is kept in sync by VersionInitialization and by the VersionProjectSettings.CurrentFileVersion setter.

Fields

// System.Version values (Major.Minor.Build.Revision)
public static Version CurrentFileVersion; // latest supported version
public static Version MinFileVersion;     // minimum backward-compatible version

These are System.Version values, so you can compare them directly with <, >, ==, etc.

Typical usage

Gate loading by version

Use the min/current values to validate save data, content packs, or networked payloads.

using System;

bool IsSaveSupported(Version saveVersion)
{
    // Must be >= minimum AND <= current
    return saveVersion >= VersionControl.MinFileVersion &&
           saveVersion <= VersionControl.CurrentFileVersion;
}

Example: save header check

[Serializable]
public struct SaveHeader
{
    public string productName;
    public string guid;
    public string version; // serialized as string "2.0.0.0"
}

bool TryValidate(SaveHeader header, out string reason)
{
    if (!Version.TryParse(header.version, out var v))
    {
        reason = "Invalid version format.";
        return false;
    }

    if (v < VersionControl.MinFileVersion)
    {
        reason = $"Save too old. Min supported: {VersionControl.MinFileVersion}";
        return false;
    }

    if (v > VersionControl.CurrentFileVersion)
    {
        reason = $"Save from newer build. Current: {VersionControl.CurrentFileVersion}";
        return false;
    }

    reason = null;
    return true;
}

Bumping versions (editor-driven)

You normally bump versions via editor UI and build menus:

  • Project Settings → Core Framework → Version Settings (VersionProjectSettingsProvider) edits the numbers.
  • Core Framework → Build → (0..3) (BuildProcessing) increments parts and applies to VersionProjectSettings.CurrentFileVersion.

Those flows then update VersionControl automatically.

Notes

  • VersionControl is read at runtime; values are written from editor-side systems.
  • In Player builds, ensure your save/load code writes a version string/number that can be parsed to System.Version.
  • If you need custom compatibility rules (e.g., allow specific hotfix revisions), implement those checks on top of these two values.
